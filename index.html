the enlightenment

Rank by cumulative cost, not model time.

✗ what we ranked by
cost = model.runtime
a single model's own time → picks the heaviest
✓ what actually matters
cost = model.runtime + max(upstream.cost)
your runtime + the longest chain feeding you → picks the critical path

Σ = cumulative = own runtime + longest upstream Σ. The max Σ is the pipeline — the culprit int_sessions is on it; the heaviest model (Σ 18) isn't. All free from dbt's manifest.json + run_results.json.

takeaways

Stop chasing the slowest model.

  • Find the critical path, not the tallest bar.
  • dbt already emits the data — manifest.json + run_results.json, every run.
  • The DAG isn't just lineage — it's a performance model.
  • Position > raw speed. Know not just what's slow, but why.
